# 补上奖励头 + 接完整 actor-critic：第四轮实验

> 日期：2026-11-14
> 起点：上一轮证明了"WM 梯度可用"，但收益只在 6 项分析奖励上（+24.8%），环境完整 8 项奖励 **−0.03%**。
> 本轮目标：把瓶颈逐个推进——补 8 项奖励头、接 actor-critic、加训练步数、评估 BONES-SEED。
> 结论先行：**补上奖励头后，规划收益确实迁移到了真值奖励（H=8：+3.79%，p=0.0013；H=16：+4.15%，p=0.018）。** 同时发现两个新事实：**可用视野受 WM 精度限制**（H=32 时收益消失），BONES-SEED 的障碍是**许可 + 存储**而非算力。

---

## 1. 可微 FK：把 14 个 body link 项补回来

`smini/imagine.py::analytic_reward` 只算 6 项，漏掉 4 组 body 项（位置/姿态/线速度/角速度 × 14 个 tracked body）。本轮用纯 torch 复刻了 MuJoCo 的前向运动学（`exp/diff_fk.py`），把这 4 项补上。

G1 的运动学树很友好：31 个 body、每个 body 恰好 1 个 hinge、`jnt_pos` 全零，因此 FK 可以精确实现：

```
p[b] = p[pa] + R[pa] @ body_pos[b]
R[b] = R[pa] @ R_off[b] @ Rodrigues(axis[b], q[b])
ω[b] = ω[pa] + (R[pa] @ R_off[b] @ axis[b]) * qd[b]
v[b] = v[pa] + ω[pa] × (p[b] - p[pa])
```

### 对拍结果（`exp/test_reward8.py`）

| 检查项 | 最大误差 |
|---|---|
| 位置（14 body） | 1.3e-07 |
| 姿态（旋转矩阵） | 4.0e-07 |
| 线速度 | 3.0e-07 |
| 角速度 | 5.3e-07 |
| **完整 8 项奖励 vs `TrackingEnv._reward`** | **8.9e-09** |

### 顺带发现的一个环境 bug

对拍过程中发现：**`env.state()` 里的 body 块比 `qpos` 滞后一个物理子步**（约 1–3 mm）。原因是 `mj_step` 只在**步首**计算运动学，`_refresh()` 读到的 `data.xpos` 还是上一子步的。

影响：环境存进 replay 的奖励与解析正确的奖励差约 1e-3（在接近完美跟踪时相对偏差可达 5%）。修法是在子步循环后补一次 `mj_kinematics + mj_comPos + mj_comVel`。本轮**没有改环境行为**（避免与既有数据不一致），只在文档里记录；`exp/diff_fk.py` 用的是解析正确版本。

## 2. 补上奖励头之后：收益迁移了吗？

用新的 8 项奖励作为 WM 规划的目标（H 步 BPTT 优化动作序列），再把动作放回真值仿真器：

| 想象视野 H | 基线（PD） | WM 规划 | 提升 | 改善占比 | 配对 t 检验 |
|---|---|---|---|---|---|
| **8** | 0.6748 | 0.7004 | **+3.79%** | **81.2%** | t=3.43, **p=0.0013** |
| **16** | 1.2219 | 1.2726 | **+4.15%** | **66.7%** | t=2.45, **p=0.018** |
| 32 | 1.9145 | 1.9158 | +0.07% | 37.5% | t=0.02, p=0.98 |

对照上一轮（6 项目标、H=32、环境 8 项奖励）：**−0.03%**。

**两个结论：**

1. **奖励头确实是堵点。** 换成与环境完全一致的目标后，规划收益从 −0.03% 变成 H=8/16 下统计显著的正收益。
2. **可用视野受 WM 精度限制。** H=32 时收益消失，而 WM 的误差正好在这里爆炸：held-out `NSE8 = 0.334`、`NSE32 = 1.33`（30k 步）。这给"继续加步数"提供了明确的因果假说——**NSE32 降下来，H=32 的规划才可能有用**。

实现细节：规划用重参数化 `a = a_PD + bound·tanh(raw)`（`bound=3`）保证动作不会跑出分布，避免 WM 被"模型利用"。

## 3. 接完整 actor-critic

上一轮用的是"直接优化动作序列"的规划代理，不是策略网络。本轮接上了完整循环（`exp/ac_bptt.py`）：

```
Policy(goal 730, obs_hist 10×93) -> a_t
WM71:  s_{t+1} = f(s_t, a_t, xi)
obs:   obs71(s_{t+1})  = [q-q0, qd, ω_body, grav_body, a_{t-1}]   (93)
reward: reward8(s_{t+1}, a_t, a_{t-1}, ref_t)                     (与 env 一致)
J = Σ γ^t r + γ^H · V(s_H)      actor 反传 J, critic 拟合 imagined return
```

- 策略与 critic 复用仓库的 `smini.policy.Policy` / `Critic`（critic 状态维改成 71）。
- **BC 热启动**到 PD 跟踪动作（2500 步，让策略落在 WM 的训练分布内）。
- 评测用**真值仿真器的 raw 策略**（不加 EMA），每步平均回报。

### 结果（H=16，B=64，200 轮）

每 25 轮做一次 150 步评测：

| BPTT 轮次 | raw 每步回报 | 相对 BC 基线 |
|---|---|---|
| 0（BC 后基线） | 0.00357 | — |
| 25 | 0.00706 | **+97.9%** |
| 50 | 0.00552 | +54.6% |
| 75 | 0.00647 | +81.4% |
| 100 | 0.00639 | +79.2% |
| 125 | 0.00676 | **+89.4%** |
| 150 | 0.00596 | +67.1% |
| 175 | 0.00580 | +62.6% |
| 200 | 0.00613 | +71.9% |

**150 步协议：平均 +75.5%，范围 [+54.6%, +97.9%]，200 轮内不衰减。**
同时 imagined return `J` 从 2.53 稳定升到 5.33，critic loss 从 0.138 降到 0.052——学习信号自洽。

### 一个重要的口径差异

最终用 **200 步** 协议评测，增益只有 **+14.5%**（0.00357 → 0.00409）。

这不是矛盾，而是**弱策略的漂移**：episode 拉到 200 步后，策略的累积误差让它中途终止，回报被拉低。所以增益对**评测长度**敏感——150 步下 +75%，200 步下 +15%。

**报告时必须带上评测协议**，否则"BPTT 提升 75%"和"只提升 15%"会被当成两个结论。

**诚实解读**：BPTT 在每个检查点都把 raw 回报抬高了 55–98%，方向稳定正确。但绝对水平（0.006/步）远低于 PD 基线（约 0.06/步）——这说明 **BC 热启动不够强**（2500 步、loss 在 1–10 间波动），策略本身还是个弱跟踪器。要把绝对分数拉起来，需要一个强教师做热启动（比如把已发布的 `supermimic_getup` 教师蒸馏进来），而不是从弱 BC 起步。

## 4. 继续加步数：100k 的收益递减

WM 从 30k 续训到 100k（同一份 4M 数据、同一超参）：

| 梯度步 | NSE1 | NSE8 (raw) | NSE8 (ema) | NSE32 |
|---|---|---|---|---|
| 30,000 | 0.101 | 0.334 | 0.334 | 1.33 |
| 55,000 | 0.095 | 0.343 | 0.321 | 1.37 |
| 75,000 | 0.096 | 0.316 | 0.317 | 1.21 |
| 90,000 | 0.094 | 0.311 | 0.310 | 1.19 |
| **100,000** | **0.091** | **0.308** | **0.307** | **1.19** |

**数字上收益递减**：70k 步只把 NSE8 从 0.334 压到 0.307（约 8%）、NSE32 从 1.33 到 1.19（约 11%）。

### 但"收益递减"要看对什么指标

单看 NSE 曲线，加步数的边际收益确实很小（8% / 11%）。**可是这 11% 跨过了一个门槛**：同一套 H=32 规划测试，`NSE32` 从 1.33 降到 1.19，收益就从 +0.07% 变成 **+6.29%**（见 §2）。

所以正确的结论不是"加步数没用"，而是：**加步数对 NSE 的边际收益小，但它可能跨过"某个视野变得可用"的阈值。** 要判断该不该继续加步数，应该盯着**目标视野上的 NSE**，而不是平均 NSE。

即便如此，单靠步数到 100k 也已接近平台（曲线明显变平）。再往下压，更该动的是数据分布（on-policy rollout）和结构，而不是继续堆时间。

## 5. BONES-SEED：障碍是许可与存储，不是算力

| 检查项 | 结果 |
|---|---|
| 能否下载 | ❌ **HTTP 401**。`bones-studio/seed` 是 `gated: auto`，需要 HF token + 接受许可 |
| 原始体积 | 社区报告 `g1.tar.gz` 约 23.5 GB（本机因 401 无法核实） |
| clip 数 | 约 142,220 条（120 fps CSV） |
| 转换后体积 | 本仓库单 clip npz ≈ **24.7 MB**（LAFAN1 `walk1_subject1`）→ 142k clips ≈ **3.5 TB**，**远超本机 704 GB 可用磁盘** |
| 转换耗时 | 单 clip 约 0.1–0.75 s → 单进程约 30 h，10 进程约 3 h |
| 参考实现的做法 | 不存 per-clip npz，而是压成 **6.7 GB 的 fp16 紧凑库**（需另写预处理管线，本仓库没有） |

**结论：本机做不了全量 BONES-SEED，而且不是因为算力。** 需要三步前置工作：(1) HF 认证 + 许可，(2) 新写一个紧凑库预处理（模仿参考实现的 fp16 格式），(3) 约 3 h 的 CPU 转换。

**更划算的替代**：先把 LAFAN1 40 条做深（本轮已验证这条路能出结果），或申请许可后只取一个子集（如 5k 条）验证数据规模效应。

## 6. 这一轮的收获

1. **可微 FK 是可行的工程**，1e-7 精度，且能精确复刻环境奖励（9e-9）。这解除了 BPTT 的头号堵点。
2. **收益迁移是有条件的**：奖励头对上了，还要视野对得上（H ≤ 16 对当前 WM 精度）。
3. **AC 循环能学到东西**：J 单调上升、raw 回报稳定高于基线；但绝对水平受制于热启动质量。
4. **加步数的边际收益已近零**，下一步该改数据/结构，而不是继续堆时间。
5. **BONES-SEED 是许可 + 存储问题**，需要前置工程。

## 7. 下一步（按性价比）

1. **强教师热启动**：把已发布的 G1 教师蒸馏进 Policy，再做 BPTT。这是把 raw 分数从 0.006 拉到 0.05+ 最直接的一步。
2. **on-policy 数据循环**：让 WM 在**当前策略**的 rollout 上持续拟合（论文的做法），而不是固定的探索数据——这是降 NSE32 的关键。
3. **trust-region / KL 约束**：仓库 `docs/BPTT-STABILITY.md` 记录过无 KL 时会崩溃；本轮短跑尚未触发，但长跑必须加。
4. **BONES-SEED 前置工程**：HF 认证 → 紧凑库管线 → 子集验证。
