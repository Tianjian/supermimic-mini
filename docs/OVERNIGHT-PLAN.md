## 1. 阶段 A：教师底座 + BPTT（消掉策略质量混杂）

### 设计要点

- **底座 = 教师网络本身**（`supermimic_getup`，260k iters）。不是蒸馏版。
  - 理由：蒸馏会引入 RMSE≈0.049 的动作误差，而这个量级足以让平衡任务崩掉（学生 89 步 vs 教师 430 步）。直接接教师，就把"策略质量"这个变量彻底消掉。
- **接口适配**：教师是 `Pol(goal680, obs930)`。
  - `goal680` = 10×68 anchor-relative，由参考动作 `goal680(qpos, qvel, fi+t)` 逐想象步给出；
  - `obs930` = 93 维观测历史按 term-major 重排，由 WM 预测的 71 维状态经 `obs71()` 重建后滚动。
  - 实现：`exp/ac_bptt.py --teacher-base`（`TeacherBase` 包装，已验证与 evalkit 原式等价：0.5329 vs 0.5329）。
- **只做增量**：lr 沿用 2e-4，但配信赖域约束；不做 BC 热启动（`--skip-bc`，并已在代码里强制：教师底座下 BC 永远跳过）。

### 配置矩阵（9 个 run）

| 配置 | H | kl_target | 种子 |
|---|---|---|---|
| A1-a | 16 | 0（无约束基线） | 0,1,2 |
| A1-b | 16 | 0.02（信赖域） | 0,1,2 |
| A1-c | 8 | 0.02 | 0,1,2 |

每次 100 iter，B=64。`--reset-adam-on-bt` 打开（评审 E2 修复）。

### 判据

- 起手校验：教师在本协议下应 ≈ **0.3798**（脚本自动记录 `std0`）。
- **A 通过**：某配置 3 种子均值 > 起手 × 1.02，且 3/3 方向一致。
- **A 未通过**：所有配置均值 ≤ 起手 → 结论"瓶颈在 WM"，进入 B/C 的意义更明确。

## 2. 阶段 B：修 WM 的动作幅度偏置

### 问题定义（实测）

大动作三分位的 8 步 NSE 是小动作的 **3.6 倍**（`r(|a|, NSE8)=+0.412`，p=6e-83）。梯度上升因此系统性惩罚大动作，策略平均 `|a|` 被压小 9.9%，跟踪变差 25.7%。

### 设计

1. **数据分布对齐**：B 阶段一律用**教师网络**做 rollout 策略（`--teacher-policy`），保证 WM 被调到 C 阶段真正会走到的状态分布上。
2. **动作幅度课程**（`--mag-prob/--mag-scale`）：以一定概率直接把动作替换成大幅随机动作，补齐大动作区间样本。
3. **分档评测**：新增 `eval_nse_buckets`，每次评测输出小/中/大三分位的 NSE8 与 `mag_ratio = large/small`。

### 配置矩阵（3 个 WM）

| 名称 | 在线数据 | 步数 | 课程 |
|---|---|---|---|
| B_base | 100k（教师分布，常规噪声） | 6000 | 无 |
| B_mag | 100k | 6000 | p=0.2, scale=3 |
| B_mag2 | 150k | 10000 | p=0.3, scale=4 |

判据：**mag_ratio ≤ 1.5**（现 2.0）且 **on-policy ratio32 ≤ 0.25**（现 0.50）。

## 5. 无人值守的工程保障

| 风险 | 措施 |
|---|---|
| 某个 run 崩了 | `run_batch` 只记 returncode，不中断；报告里显示"无可用结果" |
| 显存不足 | 并发上限 3（实测 6 并发仅 4.9 GB） |
| 超时 | 全局 deadline 7 h；到期丢弃未启动任务，仍生成报告 |
| 会话中断 | 整个流程用 `setsid nohup` 脱离；编排器不依赖 agent 在场 |
| 参数写错 | 启动前已用 `--help` + 2-iter 冒烟逐项验证过全部 flag |
| 报告缺失 | `overnight_report.py` 对缺失结果容错（已用空结果跑通过） |

## 8. 判读规则（写进报告，避免明早误读）

1. **看 3 个种子的方向，不看单次最大值**。
2. 单 run 评测噪声约 ±0.02；差距 < 0.02 视为无差异。
3. 任何"提升"必须同时看 **存活步数**（evalkit 的 `surv`）——防止"活得久但跟踪差"。
4. 若 A 未通过而 B 通过，则 C 的结论只能说明"换 WM 后仍不行"，不能倒推"BPTT 本身不行"。
